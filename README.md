# 赛题要求


| **赛题三：Agentic智能问数在客户营销场景的应用**                                                                                                                                                                                                                                                                                                                                                           |
| --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **命题概述**：如何在客户营销场景下，构造AI Native的**取数Agent**，解决传统取数时间周期长、门槛高的问题                                                                                                                                                                                                                                                                                                                          |
| **业务场景描述**（清晰说明现实业务现状、核心瓶颈及亟需解决的必要性） 企业对于看数据、分析数据、数据决策一直有比较强的诉求。客户营销场景下，需要基于客户特征（如客户等级、性别、年龄、行为偏好）与客户指标（如资产、交易、持仓、收益）进行客户人群的筛选，并基于营销效果快速调整营销策略，因此对于取数的灵活度和时效性要求比较高。传统的数据获取与分析模式正面临严峻的瓶颈： 1、业务人员对数据的需求呈现碎片化、即时化的特点。传统的固化报表和仪表盘（Dashboard）虽然稳定，但缺乏灵活性，难以应对灵活多变的业务场景。 2、自助BI的“高门槛”假象： 尽管自助BI工具（如BO, ABI等）降低了部分门槛，但其本质仍要求业务人员具备一定的逻辑思维、数据结构认知乃至SQL基础。这导致“数据民主化”停留表面，大量取数需求依然回流至技术部门，形成研发瓶颈。 |
| **技术攻关问题描述**（提炼业务瓶颈对应的技术卡点，说明难点及现有方法不足） 1、如何有效组织企业内部知识，让大模型正确拆解用户意图，提取实体、维度、指标等关键要素。 2、如何减少大模型幻觉，减少凭空捏造。 3、如何工程化评价取数准确率。                                                                                                                                                                                                                                                                |
| **攻关任务描述**（针对每一个技术攻关问题，明确需完成的具体任务及成果形式） 1、定义出AI友好的元数据（包括但不限于表定义、指标、内部约定口径等，**可持续运营**），以及元数据的组织形式（工具设计，大模型可以通过工具获取有效的上下文），解决用户业务语言与底层复杂数据结构之间的转化鸿沟。 2、设计安全围栏模块，包括但不限于表、指标、结果的合法性验证，一方面是尽可能减少大模型幻觉，另一方面是降低大模型幻觉带来的影响。 3、设计取数评测流程，工程化衡量agent的可用性，从而快速迭代Agent能力。比如可以设计另外子agent进行SQL评价打分，再引入人工进行复核，降低复核工作量。                                                                                  |
| **现有基础**（命题单位针对技术攻关难点和攻关任务，已开展的研究工作或验证尝试及效果） 1、已设计一套元数据表（表信息、列信息、业务知识、指标），通过tool的方式让LLM调用，解决了单表多指标问题、多表单指标问题 。有两个问题：一是耗时较长；二是复杂查询问题需要用户多次交互。 2、目前评测方案以人工为主，未能实现自动化评测。                                                                                                                                                                                                                   |
| **任务目标**（技术攻关的总体目标、量化技术指标及具体成果交付形式） 1、总体目标：构建一套取数Agent原型系统，用户通过自然语言取数，将数据获取时长缩短至分钟级，并确保最终执行准确率90%以上。 2、技术指标： （1）查询响应时间：简单（单表单指标、多指标查询）、中等（多表单指标）、复杂查询（多表多指标、跨主题域）查询需在分钟级内完成； （2）最终执行准确率：自然语言转数据查询的最终执行准确率需达到工业可用标准（如 >90%）。 3、成果形式：可运行的AI智能取数原型系统、源代码、模型训练说明（如涉及）                                                                                                                       |
| **数据集描述**（赛题配套数据集的核心信息，清晰说明数据相关属性及配套要求） 1、表信息（按照维度建模理论建设的表） 客户信息表、服务经理信息表、产品信息表、服务关系表、公共维表、客户持仓表、客户资产表、客户交易表、客户资产流入流出表 2、数据集 提供用于验证的脱敏数据 3、问答对 提供问答对用于功能验证                                                                                                                                                                                                                              |
| **评分标准** 1. 设计质量，系统架构与文档质量（20%）； 2. 结果质量，AI应用工程实现质量及生成结果质量（30%）； 3. 体验性，端到端响应延迟或问答延迟（20%）； 4. 创新性，算法优化、评测方案和其他创新点（30%）。                                                                                                                                                                                                                                                                 |
