## 一、阶段目标

建立可复跑的工业级评测闭环，回答阶段二尚未覆盖的两个问题：**对照金标算不算对**、**错在哪里、如何回流改进**；并顺带采集端到端耗时基线，为体验分与阶段四优化提供数据（本阶段不做缓存/并行优化本身）。

主链路：

**金标问答对 → 批量跑 Agent SQL + 金标 SQL → Execution Match →（不一致时）Eval-Agent 归因 → 分级分流 / 人工复核 → 优质案例回流 Few-Shot**

| 交付物 | 对应 README | 验收要点 |
|--------|-------------|----------|
| 金标加载与用例集 | Step 9 前置 | 解析 `data/Q&A.xlsx`（或约定等价格式）；统一 `question` / `gold_sql` 字段 |
| EX 评测引擎 | Step 9 | Agent 结果集 vs 金标结果集比对；输出 EX 准确率、明细、失败清单 |
| 延迟基线采集 | Step 9 附带 | 评测报告含每题 / 分位数端到端耗时（prune / LLM / 围栏 / execute 可选拆分） |
| Eval-Agent 归因 | Step 10 | EX 不一致时输出错误类型 + Markdown 诊断报告 |
| 人机复核分流 | Step 11 | 高分自动过 / 模糊人工核 / 低分 Bad Case；修正案例可回流 |
| 评测入口 | — | CLI / 脚本可一键跑子集或全量；pytest 覆盖比对与加载逻辑 |

**本阶段不做**：Chat UI（阶段五）、Redis 缓存与复杂查询并行（阶段四）、最终盲测打包与 >90% 正式验收（阶段五 Step 15，本阶段先出基线数字）。

**须遵守约定**：跨表默认只按 `pty_id`/`org_id` Join（不加默认 `data_dt`）；评测执行走只读 DuckDB；不改 `data/` 原始 CSV；金标文件只读加载；Agent 侧仍只依赖 `load_metadata()` / 既有 `ask()`。

**与阶段二缺口的对应**：

| 阶段二缺口 | 本阶段落点 |
|------------|------------|
| 无标准答案，准确率未验 | Step 9 EX Match |
| 错误不可解释、难迭代 | Step 10 归因 + Step 11 回流 |
| 时间指标未系统采集 | Step 9 报告附带延迟；压测优化留给阶段四 |

## 三、预计完成步骤（原计划）

1. **金标与比对底座**：`dataset.py` 解析问答对；`execution_match.py` 定 EX 规则（列/行对齐、数值容差、空结果约定）；单测用构造用例覆盖「同结果 / 异结果」。
2. **EX 评测引擎 + 延迟采集**：`runner.py` 批量调用 `ask()` 与金标 SQL 执行；汇总 EX%、分难度（若金标有标签）、失败清单；报告写入每题耗时与 p50/p95。
3. **评测 CLI / Demo + 测试**：`querypilot eval` 或 `scripts/demo_eval.py`；子集可复跑；加载与比对 pytest 通过。
4. **Eval-Agent 归因**：EX≠1（或 Agent 失败）时调用子 Agent，输出错误类型（时间窗 / Join / 聚合口径 / 过滤条件等）与 Markdown 诊断。
5. **分级复核与案例回流**：按 EX / 置信度分流（高分自动过、模糊待核、低分 Bad Case）；人工修正 SQL/问句写入回流队列，确认后进入 `few_shots`。
6. **基线收口**：约定子集或全量跑分；落档基线准确率与延迟；更新本日志进度与距 >90% 的差距清单。

**建议顺序**：1 → 2 → 3 先拿到客观 EX（与延迟基线），再 4 → 5，最后 6；避免无数字时先堆归因与复核界面。

**完成路线（填空时按序）**

| 子步 | 内容 | 验证 |

## 六、主要文件夹 / 文件组织、交付产物与用法（eval）

> 阶段三主战场是 `querypilot/eval/`。取数仍走阶段二的 `ask()`；本阶段**不改** Pipeline 语义，只在其上做评测、归因、复核与基线。

### 6.1 本阶段主要交付成果

| 类别 | 成果 |
|------|------|
| **评测闭环** | 金标加载 → `ask`+金标执行 → Execution Match → 归因 → 复核分流 → 基线落盘 |
| **统一入口** | Python：`run_eval` / `diagnose_failures` / `build_review_queue` / `build_baseline_summary`；CLI：`querypilot eval` / `querypilot review`；脚本：`demo_eval.py` / `baseline_eval.py` |
| **eval/** | 金标、EX 比对、批跑计时、Eval-Agent、HITL 回流、基线摘要 |
| **配套** | `data/Q&A.xlsx`（只读金标）；`metadata/few_shots/`（回流目标）；`logs/eval_reports/`、`logs/review/`（运行产物，gitignore） |
| **质量保障** | `tests/test_eval_*.py` + CLI eval/review 相关用例 |

数据流：

```
data/Q&A.xlsx
    │ load_qa_cases
    ▼
┌──────────────────────────────────────────────────────────┐
│ querypilot/eval/                                         │
│  runner: ask(question) + execute(gold_sql) + 计时        │
│  execution_match: 结果集 EX                              │
│  eval_agent: 失败归因 (heuristic / +LLM)                 │
│  review: auto_pass / needs_review / bad_case → Few-Shot  │
│  baseline: EX% / 延迟 / 差距摘要                         │
└───────────────────────────┬──────────────────────────────┘
                            │
         CLI / scripts 打印与落盘 JSON·MD
```

### 6.3 常用用法

**Python**

```python
from querypilot.eval import (
    run_eval,
    diagnose_failures,
    build_review_queue,
    approve_and_reflux,
    build_baseline_summary,
    save_baseline,
)

# 1) 子集评测
report = run_eval(limit=2)
print(report.accuracy, report.failed_ids, report.p50_ms)

# 2) 失败归因（启发式）
diags = diagnose_failures(report, use_llm=False)

# 3) 复核分流；人工确认后回流金标 SQL → Few-Shot
queue = build_review_queue(report, diags)
ticket = next(t for t in queue.tickets if t.case_id == "2")
# approve_and_reflux(ticket)  # 会改 metadata/few_shots/examples.yaml

# 4) 基线摘要
summary = build_baseline_summary(report, diagnoses=diags, queue=queue)
save_baseline(summary, report=report)
```

**CLI / 脚本（PowerShell）**

```powershell
# 子集评测（不落盘）
python -m querypilot.cli eval --limit 2 --no-save

# 评测 + 启发式归因 + 复核队列
python -m querypilot.cli eval --limit 2 --diagnose --no-llm-diagnose --review --no-save

# 冒烟 Demo
python scripts/demo_eval.py --limit 2

# 全量基线收口（写 phase3_baseline.*）
python scripts/baseline_eval.py

# 人工回流（示例）
# querypilot review reflux --question "..." --sql "SELECT ..."
# querypilot review approve --queue logs/review/queue_xxx.json --case-id 2

# 阶段三测试回归
pytest tests/test_eval_dataset.py tests/test_execution_match.py tests/test_eval_runner.py tests/test_eval_agent.py tests/test_eval_review.py tests/test_eval_baseline.py tests/test_cli.py -q
```

|------|------|

| `diag_*.json` / `*_diag.json` | 错误类型、summary、suggestions、markdown |
| `queue_*.json` / `*_review.json` | auto_pass / needs_review / bad_case |

### 6.4 边界（阶段三不做 / 留给后续）

- **不做**：Chat UI、Redis 缓存与复杂查询并行、正式盲测冲 >90%（阶段四 / 五）。
- **提准**：用归因 + 复核回流改 Few-Shot / 剪枝 / Prompt，再 `baseline_eval` 复测。
- **提速**：阶段四；本阶段只采集延迟基线。
