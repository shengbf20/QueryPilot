## 一、阶段目标与产物

### 1.1 本阶段目标（对齐 README Step 14；Step 15 后置）

完成**可演示的问数原型壳**：自然语言经 HTTP 进入、经 Chat UI 展示剪枝摘要、分阶段耗时、SQL、结果表，并支持 CSV 导出。

| 评分维度 | 本阶段如何支撑 |
|----------|----------------|
| 体验性 20% | UI 展示 `StageTiming` / `cache_hit`；冷热同问 Demo |
| 设计质量 / 结果质量 | API/UI 与 Pipeline **解耦包装**；准与快的证据仍用既有评测/压测（**本阶段不汇编**） |

### 1.2 本阶段交付产物

| 交付物 | 验收要点 |
|--------|----------|
| HTTP API | FastAPI：`GET /health`、`POST /api/ask`、`POST /api/export`；包装 `ask()`；JSON 含 timing / prune 摘要 |
| CLI `serve` | `querypilot serve [--host] [--port]` 可起服务 |
| Chat UI | Vite + React：问数 → 时间线/剪枝 → SQL → 表 → 导出 |
| API 单测 | 序列化纯函数测 + `TestClient` mock `ask` |

### 1.3 本阶段明确不做（后置 / 另线）

| 项 | 说明 |
|----|------|
| 盲测复跑 / `phase5_blind_eval` | Step 15；等 Agent 性能优化告一段落后再跑 |
| 交付打包 / 架构图 / 元数据手册 / 评测汇编 | 文书与归档后置 |
| Agent 提准 / 压测战役 | 可与本阶段**并行**，但不纳入本日志验收 |
| 鉴权、WebSocket 流式、重型队列、向量 Few-Shot | 不做 |
| 改 `data/` CSV、官方金标 | 不做 |

**须遵守约定**：元数据仍经 `load_metadata()` / `get_metadata()`；跨表默认 `pty_id` / `org_id`；不提交 `.env`；API/UI **只包装** `ask()`，不另起 NL2SQL。

### 1.4 成功标准（可验证）

| # | 成功标准 | 验证方式 |
|---|----------|----------|
| S1 | `PipelineResult` → API JSON（timing、prune 摘要、JSON 安全 rows） | `pytest tests/test_api_serialize.py` |
| S2 | HTTP 可 ask + 导出 CSV；同题二次可见 `cache_hit`（默认开缓存） | `TestClient` + 本地 `serve` 手测 |
| S3 | Chat UI 走通：问数 → 时间线/剪枝 → SQL → 表 → 导出 | 浏览器联调 |
| S4 | 相关 pytest 绿；不破坏既有阶段二/三/四测试 | `pytest -q` |

## 二、衔接、并行与排期

### 2.1 上游输入

```
ask() / PipelineResult / StageTiming / cache_hit
        │
        ├─► Track API（序列化 → FastAPI → serve）
        │         │
        │         └─► 契约 JSON 冻结
        │                   │
        └─► Track UI ◄──────┘（可先 mock，再接真 API）
```

| 上游 | 本阶段用法 |
|------|------------|
| `ask()` | `/api/ask` 唯一业务入口 |
| `StageTiming` | UI 时间线 |
| `PrunedSchema` | 抽 `prune_summary` 短字段，不回传整段 prompt schema |
| 阶段四缓存 | Demo：冷问 → 热问毫秒级 |

准确率分层（官方 / Extra36 / Extra2）见阶段四续一/续二日志；**本阶段不验收、不复跑**。

### 2.2 与性能优化的并行约定

| 线 | 可碰文件（倾向） | 少碰 / 协调 |
|----|------------------|---------------|
| 性能优化（另线） | `pipeline` / `cache` / `prompt` / `safety` / `metadata_engine` | 尽量保持 `ask()` **对外参数与返回字段语义**稳定 |
| 本阶段 API/UI | `querypilot/api/`、`frontend/`、`cli.py` 的 `serve`、序列化辅助、API 测试 | 少改 Pipeline 核心；若必须加字段，优先加在 `extras` / 摘要层 |

> UI 脚手架可在契约示例 JSON 写出后与 API 实现**并行**；真联调建议 API `serve` 可跑之后再接。

### 2.3 建议排期

```
Day 1  API-1 契约 + to_api_dict + 序列化单测
Day 2  API-2 FastAPI 三端点 + serve + TestClient
Day 3  UI-1 脚手架 + mock 契约渲染主界面
Day 4  UI-2 接真 API + 冷热 Demo + 导出
Day 5  联调收口：pytest + 本文勾选 + README 三行 API/UI 速查
```

可压缩：Day 1 契约定稿后，Day 2～3 API 与 UI mock **并行**。

#### API-1：契约与序列化

**问题**：`PipelineResult` 含不可直接 JSON 的对象；UI 只需短摘要。

**做法**：

1. 冻结响应字段（实现后贴一份示例到本文附录或 `frontend` mock）：

```text
ok, question, sql, rationale, tables, columns, rows, row_count,
degraded, message, probe_message, probe_suggestions, corrected, stage,
timing: { prune_ms, generate_ms, l1_ms, l2_ms, execute_ms, probe_ms, total_ms, cache_hit },
prune_summary: { tables, metrics?, bridge_tables? },
extras
```

2. 实现 `to_api_dict()`（`agent/models.py` 或 `api/schemas.py`）。
3. `rows`：日期 / Decimal → JSON 安全类型。

**涉及**：`querypilot/agent/models.py` 和/或 `querypilot/api/schemas.py`，`tests/test_api_serialize.py`

**验证**：

```powershell
pytest tests/test_api_serialize.py -q
```

---

#### API-2：FastAPI 端点与 `serve`

| 端点 | 行为 |
|------|------|
| `GET /health` | `{"status":"ok"}` |
| `POST /api/ask` | body：`question`；可选 `use_cache` / `max_rows` / `use_parallel` → `ask()` → API-1 JSON |
| `POST /api/export` | body：`columns` + `rows` → CSV 附件 |

1. `create_app()`；开发期开 CORS（`localhost` UI）。
2. 依赖：`fastapi`、`uvicorn` 写入 `pyproject.toml` / `requirements.txt`。
3. CLI：`querypilot serve [--host 127.0.0.1] [--port 8000]`。

**不做**：鉴权、WebSocket、强制 Redis。

**涉及**：`querypilot/api/*`、`querypilot/cli.py`、依赖文件、`tests/test_api_routes.py`

**验证**：

```powershell
pytest tests/test_api_routes.py -q
querypilot serve --host 127.0.0.1 --port 8000
# POST /api/ask 冷路径；同题再 POST，timing.cache_hit == true
```

### Track Chat UI

> 前置：至少具备 **API-1 契约示例**（可用 mock）；真联调需 API-2 `serve` 可用。

#### UI-1：脚手架与 mock 主界面

1. `frontend/` 初始化 Vite + React（TypeScript）。
2. `vite.config` proxy：`/api` → `http://127.0.0.1:8000`（或环境变量基址）。
3. 用 mock JSON 渲染：输入框、发送、时间线、剪枝摘要、SQL、表格、导出按钮占位、错误/探针区。

**验证**：`npm run dev` 仅 mock 可看全布局。

---

#### UI-2：接真 API

1. 发送 → `POST /api/ask`；loading / 错误态。
2. 绑定真实 `timing` / `prune_summary` / `sql` / `rows`。
3. 导出 → `POST /api/export` 触发下载。
4. 展示 `degraded` / `probe_message`。

**Demo 剧本**：冷问一句 → 同句再问 → UI 显示 `cache_hit` 与明显更短 `total_ms`。

**验证**：浏览器走通 S3；无需全量金标。
