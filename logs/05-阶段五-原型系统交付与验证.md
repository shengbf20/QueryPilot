## 一、阶段目标与产物

### 1.1 目标（对齐 README Step 14–15 + 评分维度）

完成**可演示的端到端原型**：自然语言经 HTTP/UI 问数，透明展示剪枝与分阶段耗时，输出 SQL 与结果表并可导出；在赛题/自建金标上复跑确认 EX **>90%** 叙事；打包源码、架构图、元数据维护手册与评测/压测报告。

| 评分维度 | 本阶段如何支撑 |
|----------|----------------|
| 设计质量 20% | 架构图 + 元数据维护手册；API/UI 与 Pipeline 解耦 |
| 结果质量 30% | 盲测复跑归档；安全围栏仍由既有 `ask()` 路径保证 |
| 体验性 20% | UI 展示 `StageTiming` / `cache_hit`；冷热 Demo；阶段四延迟证据复用 |
| 创新性 30% | 既有 Join-Graph 剪枝 + EX/Eval-Agent/HITL 闭环在交付材料中讲清 |

### 1.2 交付产物

| 交付物 | 对应 README | 验收要点 |
|--------|-------------|----------|
| HTTP API | Step 14 前置 | FastAPI：`/health`、`/api/ask`、`/api/export`；包装 `ask()`；可序列化响应含 timing / prune 摘要 |
| Chat UI | Step 14 | 对话问数；思考/剪枝过程；SQL 预览；数据表；一键导出 |
| 盲测复跑报告 | Step 15 | 官方默认轨 + Extra-A/B；写出 `logs/eval_reports/phase5_*`；支撑 >90% 叙事 |
| 交付打包 | Step 15 | 源码清单/zip（排除密钥与本地 DB）、架构图、元数据手册、评测与压测报告 |
| CLI / 脚本入口 | — | `querypilot serve`（或等价）；`scripts/phase5_blind_eval.py`；`scripts/phase5_package.py` |

**本阶段不做**：重开 Extra-B H01/H07 提准战役；补阶段二遗留的向量 Few-Shot 检索；鉴权 / WebSocket 流式 / 重型任务队列；改动 `data/` 原始 CSV；为不可能场景堆错误处理。

**须遵守约定**：元数据只经 `load_metadata()` / `get_metadata()`；跨表默认按 `pty_id` / `org_id` Join；不提交 `.env` 密钥；Agent 语义仍以 `ask()` 为准，API/UI 只做包装与展示。

### 1.3 成功标准（可验证）

| # | 成功标准 | 验证方式 |
|---|----------|----------|
| S1 | `PipelineResult` 可稳定序列化为 API JSON（含 timing、prune 摘要、JSON 安全 rows） | 纯函数 pytest，无 LLM/DB |
| S2 | 无前端时可用 HTTP 完成 ask + CSV 导出；热路径可见 `cache_hit` | `TestClient` + 本地 `serve` 手测 |
| S3 | 盲测脚本可复跑官方/Extra 双轨，退出码反映是否仍 ≥90% | `phase5_blind_eval.py`（可先 `--limit` 冒烟） |
| S4 | 打包脚本 dry-run 列出路径；可生成 `dist/` 清单（及 zip） | `phase5_package.py --dry-run` |
| S5 | Chat UI 演示：问数 → 时间线/剪枝 → SQL → 表 → 导出 | 浏览器联调 Demo 剧本 |
| S6 | 交付物齐备：架构图、元数据手册、评测/压测报告、运行说明 | 人工对照清单 |
| S7 | 全量 `pytest` 绿；实现不破坏阶段二/三/四既有行为 | `pytest` |

## 二、与其他阶段的衔接和安排

### 2.1 依赖与输入（上游）

```
阶段一–二   metadata + ask() Pipeline + L1/L2
     │
阶段三      EX 评测 + Eval-Agent + HITL；续一/续二 >90% 叙事
     │
阶段四      StageTiming / cache_hit / use_cache / 压测报告
     │
     ▼
阶段五      API 序列化 → HTTP → Chat UI → 盲测复跑 → 交付打包
```

| 上游产物 | 本阶段如何用 |
|----------|--------------|
| `ask()` / `PipelineResult` / `StageTiming` | API 直接调用；UI 展示分阶段耗时与 `cache_hit` |
| `PrunedSchema` | 抽短摘要 `prune_summary`（表/指标/补全中间表），不默认回传整段 prompt schema |
| 续一/续二评测数字与报告 | Step 15 叙事主证据；复跑确认，不重开提准 |
| `logs/04-phase4_perf.md` / `perf_reports` | 体验性佐证写入交付文档 |
| `eval/runner.py` / `scripts/baseline_eval.py` | 盲测脚本薄封装复用 |
| `frontend/`、`querypilot/api/` 占位 | 本阶段填实 |

### 2.2 工作分流（严格执行顺序）

> **原则**：先完成全部**项目侧代码**（Wave A），再做**前端与文书**（Wave B）。Wave B 不回头改 Pipeline 核心，除非联调暴露硬 bug。

```
Wave A（项目侧代码）
  A0 本规划日志
  A1 PipelineResult → API DTO / prune_summary
  A2 FastAPI（health / ask / export）+ CLI serve + 依赖
  A3 盲测复跑脚本 + 打包脚本
  A4 pytest 收口 + 本日志勾选 + README API 速查三行

Wave B（前端 / 文书）—— A 全部 ✅ 后才开始
  B1 Chat UI（Vite + React）
  B2 架构图、元数据维护手册、评测汇编
  B3 交付包与答辩 Demo 剧本
```

| 类别 | 包含 | 不含（推后或排除） |
|------|------|-------------------|
| Wave A 项目侧代码 | 序列化、FastAPI、导出、盲测/打包脚本、pytest、依赖与 `serve` | React 页面、架构图美化、手册正文、最终文书 zip 整理 |
| Wave B 前端/文书 | Chat UI、联调演示、架构图、元数据手册、报告汇编、交付归档 | 再改 Pipeline 核心逻辑（硬 bug 除外） |

### 2.3 与准确率工作的边界

| 工作流 | 主责 | 本阶段态度 |
|--------|------|------------|
| 官方/Extra 双轨 >90% | 续一/续二已收口 | **复跑确认 + 归档**；不以新战役冲满分 |
| Extra-B H01 / H07 缺口 | 续二已记可选 | **不阻塞**阶段五开工 |
| 向量 Few-Shot | 阶段二遗留 | **不做** |
| 缓存 / 并行 / 压测 | 阶段四已完成 | 只消费，不再排性能战役 |

### 2.4 建议排期顺序

```
Wave A
  Day 1  A0（本文）✅ → A1 序列化 + 单测
  Day 2  A2 FastAPI + serve + TestClient
  Day 3  A3 盲测/打包脚本 + pytest 全绿 + 勾选 A

  Day 4  B1 Chat UI 主路径联调

### 总体文件框架（计划落地）

```
querypilot/
├── agent/
│   └── models.py             # ✏️ to_api_dict / prune 摘要（或放 api/schemas）
├── api/                      # 🆕 填实阶段五预留

├── phase5_blind_eval.py      # 🆕 官方 + Extra 双轨复跑

├── test_api_serialize.py     # DTO / rows JSON 安全
└── test_api_routes.py        # TestClient + mock ask

frontend/                     # Wave B：Vite + React Chat UI
docs/ 或 logs/ 附图           # Wave B：架构图、元数据手册

**刻意简化的决策**：

1. 后端 **FastAPI + uvicorn**；前端 **Vite + React** 轻量单页；不引入鉴权与流式。

3. 导出 CSV 由 API 提供，UI 只触发下载。
4. 打包排除：`.env`、`db/*.duckdb`、`__pycache__`；`data/` 原始大文件按 README 约定处理，不把密钥打进 zip。

### 步骤 A1：`PipelineResult` → API 可序列化 DTO

**解决什么问题**

`PipelineResult` 含 `PrunedSchema` 等不可直接 JSON 的字段；UI 需要短摘要而非整段 schema prompt。

**具体做法**

1. 增加 `to_api_dict()`（`agent/models.py` 或 `api/schemas.py`）：
   - 基础：`ok / question / sql / rationale / tables / columns / rows / row_count / degraded / message / probe_* / corrected / stage`
   - `timing`：`StageTiming.to_dict()`（已有）
   - `prune_summary`：表名、指标名、补全中间表等短列表
   - `extras`：透传 `parallel` 等标记
2. `rows`：日期 / Decimal 等转为 JSON 安全类型；尊重 `max_rows`。

**涉及文件**：`querypilot/agent/models.py`（和/或 `querypilot/api/schemas.py`）、`tests/test_api_serialize.py`

**验证**

```powershell
pytest tests/test_api_serialize.py -q
```

### 步骤 A2：FastAPI 层（health / ask / export）

**解决什么问题**

`querypilot/api/` 仅占位；前端与外部 Demo 需要稳定 HTTP 契约。

**具体做法**

| 端点 | 行为 |
|------|------|
| `GET /health` | 进程存活 |
| `POST /api/ask` | body：`question`；可选 `use_cache` / `max_rows` / `use_parallel`；内部调 `ask()`；返回 A1 DTO |
| `POST /api/export` | body：`columns` + `rows`（或等价）；返回 CSV 附件 |

1. `create_app()` + routes；依赖加入 `fastapi`、`uvicorn`（`pyproject.toml` / `requirements.txt`）。
2. CLI：`querypilot serve [--host] [--port]`（与现有 `cli.py` 风格一致）。
3. **不做**：鉴权、WebSocket、强制 Redis、异步队列。

**涉及文件**：`querypilot/api/*`、`querypilot/cli.py`、`pyproject.toml`、`requirements.txt`、`tests/test_api_routes.py`

**验证**

```powershell
pytest tests/test_api_routes.py -q
# 手动：querypilot serve → POST /api/ask 冷路径 + 同题热路径见 cache_hit
```

### 步骤 B1：Chat UI（Step 14）—— Wave A 完成后

**解决什么问题**

业务侧需要可视化信任感：看到剪枝命中了什么、各阶段花了多久、SQL 与结果是否合理。

1. 输入问句 → `POST /api/ask`
2. 时间线：剪枝 / 生成 / L1 / L2 / 执行 + `cache_hit` 徽章
3. Schema 剪枝摘要（`prune_summary`）
4. SQL 预览（等宽）
5. 结果表 + `POST /api/export` 下载 CSV
6. 降级 / 探针文案（`degraded` / `probe_message`）

**Demo 剧本**：冷问一句 → 再问同句打出毫秒级（消费阶段四缓存）。

**涉及文件**：`frontend/*`

## 五、风险与简化策略

| 风险 | 应对 |
|------|------|
| 把阶段五做成「再提准」导致范围爆炸 | 准确率只复跑归档；H01/H07 / 向量 Few-Shot 不做 |

| 前端技术栈过重拖期 | 固定 Vite+React 轻量单页；无鉴权无流式 |
| 盲测复跑受 API Key / 环境波动 | 主叙事锁定续一/续二数字；复跑差异写进报告即可 |
| Wave B 提前开工导致 API 契约反复 | **严格执行 A→B**；先稳定 JSON 契约再写 UI |
