## 一、阶段目标与产物

### 1.1 目标（对齐 README Step 14–15 + 评分维度）

完成**可演示的端到端原型**：自然语言经 HTTP/UI 问数，透明展示剪枝与分阶段耗时，输出 SQL 与结果表并可导出；在赛题/自建金标上复跑确认 EX **>90%** 叙事；打包源码、架构图、元数据维护手册与评测/压测报告。

| 评分维度 | 本阶段如何支撑 |
|----------|----------------|
| 设计质量 20% | 架构图 + 元数据维护手册；API/UI 与 Pipeline 解耦 |
| 结果质量 30% | 盲测复跑归档（主轨 Extra36 + 官方；附录 Extra2）；围栏/确定性改写仍走既有 `ask()` |
| 体验性 20% | UI 展示 `StageTiming` / `cache_hit`；冷热 Demo；阶段四延迟证据复用 |
| 创新性 30% | Join-Graph 剪枝 + EX/Eval-Agent/HITL；续一「L1 作用域 + 无 LLM 确定性改写」与续二「清新 held-out」写入答辩材料 |

### 1.2 交付产物

| 交付物 | 对应 README | 验收要点 |
|--------|-------------|----------|
| HTTP API | Step 14 前置 | FastAPI：`/health`、`/api/ask`、`/api/export`；包装 `ask()`；可序列化响应含 timing / prune 摘要 |
| Chat UI | Step 14 | 对话问数；思考/剪枝过程；SQL 预览；数据表；一键导出 |
| 盲测复跑报告 | Step 15 | **主轨**：官方默认 + Extra36-A/B；**附录**：Extra2-A/B（可选同脚本开关）；写出 `logs/eval_reports/phase5_*` |
| 交付打包 | Step 15 | 源码清单/zip（排除密钥与本地 DB）、架构图、元数据手册、评测与压测报告（含续一/续二证据路径） |
| CLI / 脚本入口 | — | `querypilot serve`（或等价）；`scripts/phase5_blind_eval.py`；`scripts/phase5_package.py` |

**本阶段不做**：再开 Extra36 / Extra2 提准战役（缺口已由阶段四续一/续二消化）；为官方关短路 case6（24≠25）硬对齐怪癖 SQL；补阶段二遗留的向量 Few-Shot 检索；鉴权 / WebSocket 流式 / 重型任务队列；改动 `data/` 原始 CSV 与官方 `Q&A.xlsx`；为不可能场景堆错误处理。

**须遵守约定**：元数据只经 `load_metadata()` / `get_metadata()`；跨表默认按 `pty_id` / `org_id` Join；不提交 `.env` 密钥；Agent 语义仍以 `ask()` 为准，API/UI 只做包装与展示。

### 2.1b 准确率与评测集分层（对齐续一/续二，强制）

> 续二原文约定：Extra2 EX **不替代**官方 7/7 与 Extra36 双轨；答辩作「第二 held-out」附录。续一日志下游指向：盲测叙事复用续一数字。

| 层级 | 集合 | 冻结收口数字（交付叙事） | 阶段五态度 |
|------|------|--------------------------|------------|
| **主轨 L0** | 官方默认（开短路） | **7/7 = 100%**（`official_p4x1_default`） | 复跑必跑；产品演示默认行为 |
| **主轨 L1** | Extra36-A（关短路 fs=3） | **36/36 = 100%**（`extra_p4x1_A_fs3`） | 复跑必跑；泛化主证据 |
| **主轨 L1** | Extra36-B（关短路 fs=0） | **36/36 = 100%**（`extra_p4x1_B_fs0`） | 复跑必跑；无 few-shot 压力测 |
| **附录 L2** | Extra2-A/B（清新 40 题） | S5 基线曾 87.5% / 82.5%；提准后 **40/40**（`extra2_*_final2`） | 打包与答辩附录；**不以满分替代主轨**；复跑可选 |
| **对照说明** | 官方关短路 fs=3 | **6/7**（case6：pred24≠gold25） | **不攻坚**；金标扇出/未使用 CTE quirk；开短路仍 7/7 |

历史对照（勿再当阶段五主数字）：阶段三续二收口 Extra-B 曾为 **34/36**；其后 `extra_fast_B` 一度 **33/36**（含 H02 围栏假阳性）；**以阶段四续一 `extra_p4x1_B_fs0` 的 36/36 为准**。

### 2.2 工作分流（严格执行顺序）

> **原则**：先完成全部**项目侧代码**（Wave A），再做**前端与文书**（Wave B）。Wave B 不回头改 Pipeline 核心，除非联调暴露硬 bug。

```
Wave A（项目侧代码）
  A0 本规划日志
  A1 PipelineResult → API DTO / prune_summary
  A2 FastAPI（health / ask / export）+ CLI serve + 依赖
  A3 盲测复跑脚本 + 打包脚本
  A4 pytest 收口 + 本日志勾选 + README API 速查三行

Wave B（前端 / 文书）—— A 全部 ✅ 后才开始
  B1 Chat UI（Vite + React）
  B2 架构图、元数据维护手册、评测汇编
  B3 交付包与答辩 Demo 剧本
```

| 类别 | 包含 | 不含（推后或排除） |
|------|------|-------------------|
| Wave A 项目侧代码 | 序列化、FastAPI、导出、盲测/打包脚本、pytest、依赖与 `serve` | React 页面、架构图美化、手册正文、最终文书 zip 整理 |
| Wave B 前端/文书 | Chat UI、联调演示、架构图、元数据手册、报告汇编、交付归档 | 再改 Pipeline 核心逻辑（硬 bug 除外） |

### 2.3 与准确率工作的边界

| 工作流 | 主责 | 本阶段态度 |
|--------|------|------------|
| Extra36 关短路 A/B 满分 | 阶段四续一已收口 | **复跑确认 + 归档**；禁止再开 H01/H02/H07 战役 |

### 步骤 A1：`PipelineResult` → API 可序列化 DTO

**解决什么问题**

`PipelineResult` 含 `PrunedSchema` 等不可直接 JSON 的字段；UI 需要短摘要而非整段 schema prompt。

**具体做法**

1. 增加 `to_api_dict()`（`agent/models.py` 或 `api/schemas.py`）：
   - 基础：`ok / question / sql / rationale / tables / columns / rows / row_count / degraded / message / probe_* / corrected / stage`
   - `timing`：`StageTiming.to_dict()`（已有）
   - `prune_summary`：表名、指标名、补全中间表等短列表
   - `extras`：透传 `parallel` 等标记
2. `rows`：日期 / Decimal 等转为 JSON 安全类型；尊重 `max_rows`。

**涉及文件**：`querypilot/agent/models.py`（和/或 `querypilot/api/schemas.py`）、`tests/test_api_serialize.py`

**验证**

```powershell
pytest tests/test_api_serialize.py -q
```

### 步骤 A2：FastAPI 层（health / ask / export）

**解决什么问题**

`querypilot/api/` 仅占位；前端与外部 Demo 需要稳定 HTTP 契约。

**具体做法**

| 端点 | 行为 |
|------|------|
| `GET /health` | 进程存活 |
| `POST /api/ask` | body：`question`；可选 `use_cache` / `max_rows` / `use_parallel`；内部调 `ask()`；返回 A1 DTO |
| `POST /api/export` | body：`columns` + `rows`（或等价）；返回 CSV 附件 |

3. **不做**：鉴权、WebSocket、强制 Redis、异步队列。

**涉及文件**：`querypilot/api/*`、`querypilot/cli.py`、`pyproject.toml`、`requirements.txt`、`tests/test_api_routes.py`

6. 降级 / 探针文案（`degraded` / `probe_message`）
