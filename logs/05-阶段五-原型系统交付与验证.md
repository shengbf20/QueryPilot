## 一、阶段目标与产物

### 1.1 本阶段目标（对齐 README Step 14；Step 15 后置）

完成**可演示的问数原型壳**：自然语言经 HTTP 进入、经 Chat UI 展示剪枝摘要、分阶段耗时、SQL、结果表，并支持 CSV 导出。

| 评分维度 | 本阶段如何支撑 |
|----------|----------------|
| 体验性 20% | UI 展示 `StageTiming` / `cache_hit`；冷热同问 Demo |
| 设计质量 / 结果质量 | API/UI 与 Pipeline **解耦包装**；准与快的证据仍用既有评测/压测（**本阶段不汇编**） |

### 1.2 本阶段交付产物

| 交付物 | 验收要点 |
|--------|----------|
| HTTP API | FastAPI：`GET /health`、`POST /api/ask`、`POST /api/export`；包装 `ask()`；JSON 含 timing / prune 摘要 |
| CLI `serve` | `querypilot serve [--host] [--port]` 可起服务 |
| Chat UI | Vite + React：问数 → 时间线/剪枝 → SQL → 表 → 导出 |
| API 单测 | 序列化纯函数测 + `TestClient` mock `ask` |

### 1.3 本阶段明确不做（后置 / 另线）

| 项 | 说明 |
|----|------|
| 盲测复跑 / `phase5_blind_eval` | Step 15；等 Agent 性能优化告一段落后再跑 |
| 交付打包 / 架构图 / 元数据手册 / 评测汇编 | 文书与归档后置 |
| Agent 提准 / 压测战役 | 可与本阶段**并行**，但不纳入本日志验收 |
| 鉴权、WebSocket 流式、重型队列、向量 Few-Shot | 不做 |
| 改 `data/` CSV、官方金标 | 不做 |

**须遵守约定**：元数据仍经 `load_metadata()` / `get_metadata()`；跨表默认 `pty_id` / `org_id`；不提交 `.env`；API/UI **只包装** `ask()`，不另起 NL2SQL。

## 附录 A：HTTP API 使用说明与响应契约

### A.1 前置条件

- 已配置 `.env` 中 `DEEPSEEK_API_KEY`（勿提交仓库）
- 已导入本地 DuckDB（如 `db/competition.duckdb`）
- 已安装依赖：`pip install -e .`（含 `fastapi` / `uvicorn`）

### A.2 启动服务

```powershell
querypilot serve --host 127.0.0.1 --port 8000
# 开发可选：querypilot serve --reload
# 等价：python -m querypilot.cli serve --host 127.0.0.1 --port 8000
```

浏览器可打开交互文档：`http://127.0.0.1:8000/docs`（Swagger）。

### A.3 端点一览

| 方法 | 路径 | 说明 |
|------|------|------|
| `GET` | `/health` | 存活检查，返回 `{"status":"ok"}` |
| `POST` | `/api/ask` | 自然语言问数；内部调用 `ask()`，响应为 API-1 JSON 契约 |
| `POST` | `/api/export` | 将 `columns` + `rows` 导出为 CSV 附件 |

**`POST /api/ask` 请求体**

| 字段 | 类型 | 默认 | 说明 |
|------|------|------|------|
| `question` | string | （必填） | 自然语言问题 |
| `use_cache` | bool \| null | `null` | `null`=跟随全局默认；`false` 关闭缓存；`true` 开启 |
| `max_rows` | int | `1000` | 返回行数上限 |
| `use_parallel` | bool | `false` | 是否尝试规则并行路径 |

**`POST /api/export` 请求体**

| 字段 | 类型 | 说明 |
|------|------|------|
| `columns` | string[] | 表头 |
| `rows` | any[][] | 数据行（与 ask 响应中的 `rows` 同形即可） |
| `filename` | string | 可选，默认 `querypilot_export.csv` |

本地开发已对 Vite 常用源（`localhost:5173` / `3000` / `4173`）开启 CORS。

### A.4 调用示例（PowerShell 注意）

> **不要**在 PowerShell 里直接写 `curl -H ... -d "..."`：`curl` 是 `Invoke-WebRequest` 的别名，参数不兼容；手工拼 `\"` 的 JSON 也容易把中文弄坏。  
> 终端里 `question` / `rationale` 显示成 `???` 或 `ç»è®¡…`，多半是**控制台编码**问题；以业务字段为准：`ok=True`、SQL 合理、`rows` 有数即正常。可用下面脚本把完整 UTF-8 JSON 落到文件核对。

**推荐：Python 演示客户端（最稳）**

```powershell
# 需已启动 querypilot serve
python scripts/api_ask_demo.py
python scripts/api_ask_demo.py --save logs/api_ask_last.json
# 用编辑器打开 json 可正确看到中文；同题再跑一次看 cache_hit
```

**推荐：PowerShell 原生**

```powershell
Invoke-RestMethod http://127.0.0.1:8000/health

$body = @{ question = "有多少年龄大于30岁的女性客户？" } | ConvertTo-Json -Compress
$r = Invoke-RestMethod -Method Post `
  -Uri http://127.0.0.1:8000/api/ask `
  -ContentType "application/json; charset=utf-8" `
  -Body ([System.Text.Encoding]::UTF8.GetBytes($body))
$r | ConvertTo-Json -Depth 6 | Out-File -Encoding utf8 logs/api_ask_last.json
$r.ok; $r.rows; $r.timing.cache_hit
```

**可选：curl.exe（注意是 `curl.exe`，且用文件传 JSON）**

```powershell
'{"question":"有多少年龄大于30岁的女性客户？"}' | Out-File -Encoding utf8NoBOM tmp_ask.json
curl.exe -X POST http://127.0.0.1:8000/api/ask -H "Content-Type: application/json" --data-binary "@tmp_ask.json"
```

浏览器交互调试：`http://127.0.0.1:8000/docs`（Swagger，非 Chat UI）。

## 附录 B：Chat UI 使用说明

### B.1 是什么

`frontend/` 为 Vite + React + TypeScript 单页问数界面，经开发服务器代理调用附录 A 的 HTTP API，展示：

- 分阶段耗时时间线与 `cache_hit`
- Schema 剪枝摘要（种子表 / 桥接表）
- SQL 预览、结果表
- 降级 / 探针文案
- CSV 导出（`POST /api/export`）

主实现：`frontend/src/App.tsx`、`frontend/src/api.ts`；契约类型：`frontend/src/types.ts`。  
更短的联调说明也见 [`frontend/README.md`](../frontend/README.md)。

### B.2 前置条件

| 用途 | 需要 |
|------|------|
| 真问数（「发送」） | `.env` 中 `DEEPSEEK_API_KEY`；本地 DuckDB 已导入；**先** `querypilot serve` |
| 仅看布局 | Node.js / npm；可不启后端，用页面上的 mock 按钮 |
| 依赖 | 后端：`pip install -e .`；前端：`cd frontend && npm install` |

### B.3 启动（双终端）

**终端 1 — API（真问数必开）**

```powershell
querypilot serve --host 127.0.0.1 --port 8000
# 自检：浏览器打开 http://127.0.0.1:8000/health → {"status":"ok"}
```

**终端 2 — Chat UI**

```powershell
cd frontend
npm install
npm run dev
```

浏览器打开终端提示地址（默认 **`http://127.0.0.1:5173`**）。  
`vite.config.ts` 将 `/api`、`/health` 代理到 `http://127.0.0.1:8000`，前端代码里写相对路径即可。

> 不要用 `http://127.0.0.1:8000/docs` 当 Chat UI——那是 Swagger，不是本附录的页面。

### B.4 页面操作

| 控件 | 行为 |
|------|------|
| 输入框 | 填写自然语言问题 |
| **发送** | `POST /api/ask`；loading 时按钮禁用；失败显示错误条（含「请先 serve」类提示） |
| **导出 CSV** | 将当前结果的 `columns`/`rows` 提交 `/api/export` 并下载 |
| **mock 成功** | 本地附录 A 样例，不打后端 |
| **mock 拦截** | 本地围栏/探针样例，不打后端 |

结果区依次为：分阶段耗时 → 剪枝摘要 → SQL → 结果表 →（如有）降级/探针。

### B.5 冷热 Demo 剧本（体验性）

1. 确保 API 与 UI 均已启动。  
2. 输入例如：`有多少年龄大于30岁的女性客户？`，点 **发送**（冷路径，数秒级，`cache_hit=false`）。  
3. **不要改问句**，再点一次 **发送**（热路径，`cache_hit=true`，`total_ms` 通常明显更短）。  
4. 点 **导出 CSV** 验证下载。  
5. （可选）输入危险写操作类问句或点 **mock 拦截**，查看探针区展示。

### B.6 常见问题

| 现象 | 处理 |
|------|------|
| 发送报错「无法连接 API」 | 先起 `querypilot serve`；确认 8000 端口未被占用 |
| 页面空白 / `npm` 报错 | 在 `frontend/` 下执行 `npm install` 后再 `npm run dev` |
| 代理到错端口 | 改 `frontend/vite.config.ts` 中 `server.proxy` 的 `target`，与 serve 端口一致 |
| 只要布局、无 Key | 用 **mock 成功 / mock 拦截**，无需后端 |
| 与附录 A 的 curl 混淆 | Chat UI 在 **5173**；API/Swagger 在 **8000** |
