## 3. 真错题号与典型原因

通道问题的题号不列（空回复 / 截断 JSON / 504）。下面只列校正后仍错的题。

### AWS-GPT-5.6-Luna — Extra2 fast **FM13**

按分公司汇总 2026 年一季度客户交易额。金标只要 `up_org_name` + 金额两列；预测多输出了 `org_name`（营业部粒度）。**列数 3 vs 2。**

### MiniMax-M3 — Extra36 fast **H04**；Extra2 fast **FM16**；Extra2 agent **FE08**

- **H04**：一季度现金转入 >10 万且 3 月 31 日持有开放式基金。过滤偏松（产品类型 / 去重不够），**行数 213 vs 47**。
- **FM16**：一季度交易过产品代码 `002131` 的客户人数。预测 SQL 为空或无结果列，**列数 0 vs 1**。
- **FE08**：南京某营业部客户人数。金标只要 `COUNT`；预测按 `org_name` 分组多出一列，且网点匹配过宽。**列数 2 vs 1。**

### Kimi-K2.5 — 官方 fast/agent **4**；Extra2 fast **FM06**

- **官方 4**：分公司+营业部的客户省/市分布。金标有 `city_name`（5 列）；预测只到省（4 列）。快慢路径同错。
- **FM06**：2026-03-31 按币种汇总持仓市值。金标是 `ccy` + `SUM(mkt_val)`；预测多了一列币种中文名。**列数 3 vs 2。**

### mimo-v2.5-pro — Extra2 fast **FM06**

与上题同一金标。预测把 `ccy` 换成了中文名，结果集对不上。**row multiset mismatch。**

### GLM-5.3 — Extra2 fast **FE08**

与 MiniMax 的 FE08 同类：营业部人数题多输出了 `org_name`。**列数 2 vs 1。** 快路径同题是 JSON 截断，已按通道问题剔除。

### deepseek-v4-flash（官方 Agent）— Extra36 agent **H01**

紫金理财钻石卡 + 持仓 + 26Q1 盈亏。6 轮工具预算用尽，没有可用 SQL。快路径关思考后此题已过，属 Agent 编排/预算问题，不是空 `content`。

### 校正后无真错

Qwen3.8-Max（原始 12 处全是 504）、DeepSeek-V4-Flash-0731-Instruct（18 处全是空 `content`）、AWS-Gemini-3.1-Pro-Preview（22 处全是 JSON 截断）、`logs/11` 官方基线。
