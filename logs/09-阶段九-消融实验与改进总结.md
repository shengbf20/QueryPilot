# 09-阶段九：消融实验与改进总结

## 一、改进概述

### 1.1 金标SQL公式修正

**问题发现**：H01和FH01的金标SQL盈亏计算公式存在错误。

**问题分析**：
```sql
-- 错误公式（原金标SQL）
coalesce(aset_end.nm_tot_aset, 0) + coalesce(aset_end.fc_pur_aset, 0)
  - coalesce(aset_bgn.nm_tot_aset, 0) + coalesce(aset_bgn.fc_pur_aset, 0)  -- ❌ 缺少括号
  + coalesce(fin.aset_out, 0) - coalesce(fin.aset_in, 0) AS aset_pft

-- 正确公式（修正后）
coalesce(aset_end.nm_tot_aset, 0) + coalesce(aset_end.fc_pur_aset, 0)
  - (coalesce(aset_bgn.nm_tot_aset, 0) + coalesce(aset_bgn.fc_pur_aset, 0))  -- ✅ 添加括号
  + coalesce(fin.aset_out, 0) - coalesce(fin.aset_in, 0) AS aset_pft
```

**影响**：当客户有外币资产（`fc_pur_aset`）时，错误公式会多计算 `2 × bgn_fc`。

**修正文件**：
- `data/extra/Q&A_all.xlsx` - H01金标SQL
- `data/extra2/Q&A_all.xlsx` - FH01金标SQL

**验证结果**：修正后，full配置的H01和FH01应该能通过评测。

### 1.2 COUNT格式错误检测

**功能描述**：检测GROUP BY + COUNT(DISTINCT)返回多行（每行都是1）的情况。

**实现位置**：
- `querypilot/safety/result_probe.py` - `_check_count_format()` 函数
- `querypilot/agent/pipeline.py` - L2修正逻辑

**触发条件**：
1. SQL中有COUNT函数
2. SQL中有GROUP BY
3. 结果返回多行
4. 所有行的COUNT值都是1

**示例**：
```sql
-- 错误查询：按客户分组统计客户数
SELECT COUNT(DISTINCT pty_id) AS cnt
FROM dwd_cust_hold_d
WHERE data_dt = '20260331'
GROUP BY pty_id

-- 结果：454行，每行都是1
-- 期望：单行总数
```

**性能影响**：COUNT格式错误检测的L2修正会导致性能下降（每次触发都会调用LLM）。

**建议**：移除L2修正，保留检测和提示功能。

## 四、性能优化建议

### 4.1 移除COUNT格式错误检测的L2修正

**原因**：
1. 从评测结果看，没有案例需要这个修正
2. 移除后可以显著提升性能（避免不必要的LLM调用）
3. 系统仍然会保留检测和提示功能

**修改位置**：`querypilot/agent/pipeline.py` 第260-285行

### 4.2 修正SYSTEM_PROMPT中的错误规则

**问题**：第17条规则中的盈亏公式是错误的。

**错误规则**：
```
aset_pft 必须写成 end_nm+end_fc - bgn_nm + bgn_fc + aset_out - aset_in（注意期初 fc 前为加号）
```

**正确规则**：
```
aset_pft 必须写成 end_nm+end_fc - (bgn_nm + bgn_fc) + aset_out - aset_in（注意期初资产需要括号）
```

**修改位置**：`querypilot/agent/prompt.py` 第17条规则

### 5.1 改进成果

1. **金标SQL修正**：修正了H01和FH01的盈亏计算公式
2. **Schema优化**：优化了4个metadata文件的字段描述
3. **COUNT格式错误检测**：添加了新的检测功能

### 5.2 消融实验结论

1. **完整管线（full）**：97.4% 准确率，表现最佳
2. **Fix_sql组件**：贡献最大（+2.7%），建议保留
3. **L1组件**：贡献较小（+0%），但能防止特定错误
4. **L2组件**：贡献中等（+1.3%），能修正复杂错误

### 5.3 后续优化方向

1. **移除COUNT格式错误检测的L2修正**：提升性能
2. **修正SYSTEM_PROMPT中的错误规则**：避免LLM生成错误SQL
3. **继续优化Schema描述**：解决剩余失败案例
4. **优化L2围栏**：提高修正准确率
