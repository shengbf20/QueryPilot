## 一、目标回顾

阶段八定下的 DoD：

1. 添加一张同域新表：人类只答 ≤7 个业务问题，全程不碰代码/机制文件；
2. 旧集回归全绿 + 新表冒烟题通过；
3. 注册表动态推导，热路径代码零改动。

本阶段把 §四设想的 `table_ops` 子包全部实现，并用「服务经理域」两张模拟表做了
**逆向验证**：机器重新发现人类手写的全部元数据事实。

## 二、实施路径（三个前置重构 + 一个运维子包）

### 2.1 剪枝知识外置（11b2813）

`schema_pruner.py` 的 7 个硬编码常量（兜底表、事实表、组织维表、客户线索词、
种子黑名单、域触发词、同义扩展）外置到 `metadata/pruning.yaml`：

- `pruning_config.py` 新增 `PruningConfig` frozen dataclass + `load_pruning_config()`
  （lru_cache），文件缺失回退到与历史硬编码逐字一致的内置默认值；
- 剪枝**机制**（打分、权重、top_k、Join-Graph 扩张）留在代码里不动——
  边界约定：YAML 只放领域知识，改 YAML 不需要改代码。

### 2.2 loader 注册表动态化（9fad2f9）

`EXPECTED_TABLES` / `DB_COLUMNS` 两份手写 schema 副本删除：

- `discover_table_names()` 扫描 `metadata/tables/*.yaml`（排序输出，与原字母序清单一致，
  prompt 不变）；
- `validator.py` 的 DB 列比对检查改为按表 YAML 定义对 information_schema 校验；
- `l1_ast.py` 表白名单 = `set(catalog.keys())`，catalog 由目录扫描派生。

### 2.3 服务经理域模拟表（0da90af）

按 §五示例补赛题欠账，作为新表接入试验床（**同时是真数据**）：

- `data_sim/`：`dim_mgr_info.csv`（20 经理，归属真实营业部，seed=20260824）、
  `dwd_cust_mgr_rel_d.csv`（300 客户-经理关系，70% 同营业部分配）；
- `import_data.py` 支持 `csv_dir` 键（模拟数据目录与官方 data/ 分离，data/ 仍只读）；
- 全套手写元数据：表 YAML × 2、join_graph +3 边 +2 路径、pruning +2 域触发词组
  +`dwd_cust_mgr_rel_d` 入 fact_tables、`客户经理→服务经理` 同义扩展。

此后所有 A1-A9 的验证标准就是这套手写事实：**机器能不能重新发现它？**

### 2.4 table_ops 运维子包（零侵入）

```
querypilot/table_ops/
├── discover.py      # A1 结构发现 + A2 骨架生成
```

不被 ask/loader 任何热路径反向引用。

## 三、A1-A9 逐项记录

### A1 结构自动发现（6226ecf）

`information_schema` 列类型 + 每列 DISTINCT/null 探测 → 表画像：

- 列级：基数 / 唯一性 / 常量列（快照特征，带值）/ 日期列（全值 YYYYMMDD）；
- 表级：行数 / 层次推断（表名前缀 dim/dwd/dws/ads/ods）/ 单列主键候选（唯一且无空值）；
- 逆向验证：10 张表层次推断全部命中手写 YAML；单列主键全部重新发现；
  组合主键表的单列候选 ⊆ 声明主键集合。

**机械事实 ≠ 业务语义**：`ads_cust_info_d` 发现 `pty_id`、`sor_pty_id` 两个单列唯一键
（都是事实，业务上选 `pty_id` 是人的决定）；`dim_mgr_info` 的 `mgr_name`、`org_id`
也单列唯一（20 行恰好不重）——A1 如实报告备选，取舍留给问卷。

### A2 YAML 骨架生成（bb4bace）

A1 画像 + A3 键候选 + A4 枚举候选 → 表 YAML dict：

- 物理字段机器填（layer / 列名类型 / format YYYYMMDD / code_type_id / enum_ref /
  enum_values 骨架）；语义字段留空（alias / description / usage / 别名 / 枚举含义）；
- 主键只取核心唯一列；「快照日是否入主键」是业务约定（dim_branch 含、ads 不含）→
  notes 标注交问卷 Q3；
- 键列（A3 候选）不再产 new 枚举骨架（`mgr_id` 的值域是标识符，不是待解释枚举）。

逆向验证：10 张手写表的物理/枚举字段全部可由骨架重建，且 round-trip 可被 loader 解析。

### A3 业务键候选（9001709）

两层信号，纯机械零 LLM：

1. **名字信号**：键注册表由 join_graph 现有 15 条边双向推导（不新增维护点）；
2. **值域信号**：DISTINCT 值集包含性验证——解决「列名同 ≠ 语义同」，
   `data_dt` 因全值命中日期格式直接排除出键候选。

置信度分级（实测数据校准）：

| 分级 | 判据 | 实测依据 |
|------|------|----------|
| high（同名） | containment ≥ 0.70 | 事实表孤儿行实测 tran 0.787 / fin 0.767 / hold 0.926 |
| high（盲扫） | containment ≥ 0.90 | 非同名命中需高门槛与撞值区分 |
| medium | 0.30–0.90 | 问卷强制确认 |
| low | < 0.30 | 撞名/撞值，丢弃 |

逆向验证：join_graph 全部 15 条边，机器从某一端探测均可重新发现（同名+值域双信号）。
sim 域上 `pty_id`→ads（1.0，fact，建议 no_default_data_dt）、`mgr_id`→dim_mgr_info
（1.0，dimension）、`org_id`→dim_branch（1.0，dimension）全部 high。

**撞名教训**（FE09 的机械化重述）：初版方向过滤写错，`mgr_id` 命中注册表反向条目
产生自环候选（`dim_mgr_info.mgr_id → dwd_cust_mgr_rel_d.mgr_id`）——修正为
排除指向自身的目标 + 按目标去重（优先带 filter 的 lookup 条目）。

### A4 枚举候选（d3547fc）

三类候选，`distinct 探数 ↔ value_descriptors.yaml` 值域比对：

- **dict**：值集 ⊆ dim_public 码集 → 建议 code_type_id + lookup；
- **static**：值集 ⊆ static_enums → 建议 enum_ref；
- **new**：低基数未匹配列 → enum_values 骨架，含义留人填（Q6）。

逆向验证：5 个 code_type column_refs、6 个 static enum_refs 全部重新发现；
`mgr_title` 产出 new 枚举骨架；文本/键/日期列无误报。单值列平凡包含只给 medium
（全包含但仅 1 个 distinct 值）。

### A5 注册落盘 + cue 继承（7887f1c）

问卷答案（Q1-Q7）+ A2 骨架 → 四个元数据文件一次写齐：

- 新表 YAML（语义字段回填）；
- join_graph：tables 条目 + 确认的边（含 rules / filter）+ 可选 paths；
- pruning.yaml：**dwd/dws 层自动入 fact_tables**（客户枢纽注入生效）、
  cue_words 自动挂 domain_seed_cues；
- value_descriptors：dict 枚举列自动追加 column_refs（三方 code_type_id 一致性
  由 metadata_validator._cross_validate 兜底）。

工程要点：

- 对既有文件做**保注释、缩进自适应**的文本级插入（条目前置到块头后，
  语义与顺序无关）。实施中抓到两个文本手术 bug：固定 2 空格缩进在
  0 缩进 round-trip 文件上破坏 YAML；column_refs 块边界把 `label:` 误判出块。
- 落盘后清进程内缓存（`clear_caches()` + pruning config lru_cache 失效），
  serve/chat 场景仍建议重启。

逆向验证：在 metadata 副本上抹掉手写 sim 注册，用问卷答案重注册两张表，
alias / 主键 / 枚举含义 / join 边 / cue / fact_tables 全部与 0da90af 手写一致。

### A6 注册表同步验证（5aa272d）

`verify_registration()` 七项检查，证明「写完文件即全链路生效，零代码改动」：

目录扫描发现 → 表 YAML 可解析 → join_graph 表注册 → 边两端齐全 →
pruning 收录 → L1 白名单（catalog 派生）→ prompt 表结构渲染。

负向验证：未注册状态 loader / join_graph / L1 白名单三项同时报缺失。

### A7/A8 校验与回归编排（b5b6acf）

`run_onboarding_regression()` 四层防线，全部复用既有机制：

1. **A7 静态校验**：validate_table + join_graph 子校验器（路径参数化，
   既有校验器零改动）；
2. **YAML ↔ DB 列对齐**：information_schema 比对（缺列/多列/类型不一致）；
3. **join 边连通冒烟**：每条边真实 JOIN COUNT（0 行 = 边失效）；
4. **剪枝冒烟**：冒烟问句经 SchemaPruner 命中新表（确定性零 LLM）。

`baseline_regression()` subprocess 编排 `scripts/baseline_eval.py`（dry-run 零 LLM
走 CI 冒烟；完整回归需 API key）。

**冒烟抓到的真实行为**：「胡明经理服务了多少客户」不命中关系表——
cue 词 `名下客户` 在问句里不连续出现，机械上正确；冒烟问句必须选域内典型问法
（「服务经理名下有多少客户」等 3 问全命中）。

**负向验证**：构造坏边（`mgr_id` 错连 `mgr_title`）→ 连通数 0 被抓；
YAML 多出 DB 不存在的 ghost 列 → 对齐检查失败。

### A9 问卷生成 + 登记 CLI（9a68a1a）

`prompts.py`：

- 机械问卷 Q1-Q7 带默认答案（A1/A2/A3/A4 候选做底稿），零 LLM 可跑；
- `generate_questionnaire()` 让 LLM **只翻译 question/default 措辞**，
  机械候选（列名/目标表/置信度）逐字保留；LLM 失败/输出异常自动降级机械问卷
  ——「去掉 LLM，流水线仍 100% 可运行」从原则变成代码路径。

`cli.py`（人类唯一接触的界面）：

```
python -m querypilot.table_ops.cli questionnaire dwd_new_table_d        # 打印问卷
python -m querypilot.table_ops.cli register dwd_new_table_d --yes \
    --alias 新表 --granularity 客户级 \
    --col-desc pty_id=客户号 \
    --edge pty_id:ads_cust_info_d.pty_id:fact:no_default_data_dt \
    --cue 触发词1,触发词2 --question "冒烟问句"
```

一条命令走完：问卷 → 答案落盘（A5）→ 同步报告（A6）→ 校验回归（A7/A8），
任一环节失败即非零退出。TTY 下对缺失关键项交互补问；`--dry-run` 只渲染不写盘。

**端到端 CLI 验证**（副本上抹掉手写注册后重走）：先 `dim_mgr_info` 后
`dwd_cust_mgr_rel_d`，两次 register 均「全部同步生效 + 回归通过」。
中途还抓到一个漏填 `data_dt` 列描述的用例（A7 正确拦截）。

**顺序约束**：先注册维表、再注册引用它的事实表——中途 join_graph 短暂不一致
（边指向未注册表），A7 会抓这个状态。
