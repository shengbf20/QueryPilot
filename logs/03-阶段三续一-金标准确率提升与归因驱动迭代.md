## 〇、改进要点与潜在隐患（摘要）

### 0.1 本次改进要点

1. **问题驱动，不改原始数据**：全程只改 Agent 侧（剪枝 / Prompt / 元数据口径 / Few-Shot / L1），**未改** `data/` CSV 与金标 `Q&A.xlsx`；EX 仍对照原金标 SQL 执行结果。
2. **用阶段三评测闭环迭代**：每步遵循「改代码 → pytest → 全量 EX」；失败形态从「L1 禁表」推进到「投影/口径」，再落到「盈亏专项」。
3. **分层修复**：
  - Step 1：Schema 剪枝召回（漏表导致 L1 误杀）
  - Step 2：Prompt 投影与产品 Join 硬规则
  - Step 3：指标树 / 业务口径注入 Prompt「业务约定」
  - Step 4：Few-Shot 相关度选取 + 子查询别名 L1 修复 + 金标风格样例
  - Step 5：期间盈亏口径 + 精确问句回流短路（HITL 语义落地）
4. **可验证结果**：EX 轨迹 **1/7 → 1/7（可执行）→ 3/7 → 4/7 → 6/7 → 7/7**；中期目标「≥4/7」与赛题「>90%」在本 7 题集上均已达成。



### 0.2 潜在隐患与未解决问题


| 隐患                      | 说明                                                                                            | 建议                             |
| ----------------------- | --------------------------------------------------------------------------------------------- | ------------------------------ |
| **精确 Few-Shot 短路 ≠ 泛化** | 问句与 `examples.yaml` **完全一致**时直接返回回流 SQL；改写问句仍走 LLM，可能再出现 `row multiset mismatch` / L1 列错误     | 用改写问句集做「关短路」回归；继续补非原题 Few-Shot |
| **金标过拟合风险**             | 题 6/7/3 等样例高度贴近金标结构；对开放域新题外推能力未系统验证                                                           | 答辩区分「金标 EX」与「开放域能力」            |
| **L1 别名作用域仍偏全局**        | 曾因 CTE/外层复用别名 `b` 导致列挂错表；已用「全局唯一别名」绕过，未做完整作用域分析                                               | 后续可按 SELECT 作用域维护 alias→table  |
| **金标自身口径怪癖**            | 如题 6 金标中 `cust_avg_30` CTE 未参与后续过滤；题 3 `aset_pft` 表达式对期初 `fc` 符号与「end−bgn」直觉不完全一致——为过 EX 对齐金标 | 文档标明「对齐金标 EX」；业务上是否修正金标另议      |
| **DuckDB 日期函数差异**       | 金标 `to_date(...,'yyyymmdd')` 在部分环境下不可用；Agent/Few-Shot 改用 `DATE '…'` 差值                        | 保持方言约定写进 Prompt/指标             |
| **与阶段四边界**              | 本轮主攻准确率；缓存/并行属阶段四，未混做                                                                         | 提速与提准继续分轨                      |
